# UIと配布方式の判断

今回の優先事項は、使いやすい日本語UI、Python未導入のPCへの配布、既存の解析精度の維持、元へ戻せることです。研究用アノテーションをLLMで生成する変更は加えていません。

| 選択肢 | 利点 | 今回の判断 |
|---|---|---|
| Streamlit継続 | 既存の表・グラフをすぐ使える。実装済みで回帰テストもある | 旧UIとして維持。新しい配布では画面再実行への依存と大きな同梱物を減らす |
| PySide / Qt | デスクトップ向けのウィンドウ、豊富な部品 | 有力だが追加ランタイム、配布・OS別検証が増えるため今回は導入しない |
| Electron / Tauri | 自由なUIと専用ウィンドウ | ブラウザーエンジンやOS側WebViewへの依存を避け、今回は導入しない |
| ローカルHTML + Python | OSのブラウザーを使い、既存解析を再利用。静的アセットを同梱できる | 採用。日本語導線、レスポンシブ画面、バックグラウンド処理、プロジェクト保存を追加 |

新UIは標準HTTPサーバーを127.0.0.1に限定し、ポートを自動選択します。Host、Origin、起動ごとの操作トークンを確認し、外部ページから結果の読み出しや操作ができないよう制限します。外向けサーバーとしての公開・複数利用者向けのホスティングは想定していません。

画面は入力・探索・使い方の3画面。検索、照合状態、局在、分類、数値を組み合わせて絞り、表示列の選択・並べ替え・50件単位のページ表示ができます。独立したダイアログから根拠を読み、候補を明示的に確定します。注釈名は日本語、原データの内容は原文を保持します。

結果は解析完了時にまとめて更新します。処理失敗・中止時は前の解析を保持し、処理中の復元を禁止します。複数タブから古い結果へ変更やCSV保存を行う要求は版番号で検出します。保存済みJSONは全体を検証してから取り込み、デシリアライズに実行可能形式を使いません。外部由来の文字列をHTMLとして実行しません。

通常の入力上限は24MB・10,000行・250列。プロジェクトJSONは128MB以内です。大きな生データ応答全体を含めず、必要な注釈と出典・根拠を保持します。上限を超える場合はCSVを保存し入力を分割します。自動保存ではなく、明示的なJSON保存でPC間の移動と再開を行います。

配布はPythonと必要ライブラリをフォルダーへ同梱し、版・OS・CPU・ビルド日時別のZIPを作ります。新UIにはStreamlit、Plotly、PyArrowを同梱しません。OSをまたぐ単一実行ファイルは作れないため、各OS向けのビルド手順と手動起動のCIを用意します。ビルドできたことと、対象PCで実際に操作できたことを別々に記録します。

参考：[PyInstaller公式マニュアル](https://pyinstaller.org/en/stable/)、[Python HTTPサーバーの説明](https://docs.python.org/3/library/http.server.html)。HTTPサーバーはローカル専用とし、インターネットへの公開用途に使用しません。
